# Lane i18n-menu (menu side)

Shared core: `src/ds_i18n.h` and `tools/i18n_tool.py`, copied unchanged. `src/ds_i18n.c` is the one `DSI_IMPLEMENTATION`
of multiplayer.dylib / .dll (and of dsrig.dylib). It is in `src/build.sh` (the loader reads its source list from there),
and Windows picks it up by itself (gen_port.py takes every `src/*.c`). The tests that use translated text link it too:
`mpmenu_test`, `mp_test`, `net/` (all tests, asan too) and `net/steam`. `ui_test` and `teams_test` link none of my files,
so the other lane's own `DSI_IMPLEMENTATION` in its harness gives no duplicate. (integration: they link `src/ds_i18n.c` now; the harness file is gone.)
`.gitignore` (root whitelist): `!/tools/` and `!/lang/` added. `lang/en.json` was not committed in the lane (integration: committed, 854 keys for both lanes). A local extract of this branch gave 388 keys.

### Runtime (mpmenu.c)
- Language files: `<folder of multiplayer.dylib/.dll>/lang/<code>.json` (dladdr, as rig_det.c does). `DSMP_LANG_DIR`
  overrides it (tests). No folder = English. Windows module build: `win/build_win.sh` copies repo `lang/*.json` into
  `build/mods/multiplayer/lang/`. They are not in mod.json's files list, so they are not hashed. The Mac loader package
  (ds_launcher `loader/build.sh`) must copy `lang/` the same way: that is the loader's repo, not done here.
- Poll: `lang_poll()` once per `mpmenu_frame`. It resolves `Refactor.Setting.LanguageSetting.GetCurrentLanguage` by name
  and calls it only when the class's static fields exist. Then `dsi_set_lang`. Before that: English.
- On a change on the title screen: all title clones are destroyed (column rows, Recent worlds, Rules / Expedition Rules /
  host-choice panels, address + name fields, the load-list toggle, the "Remove tag" texts). `title_sync` rebuilds them on
  the same frame in the new language and fonts. Campaign UI (lobby, Esc buttons, chat) is built per scene, and the
  language cannot change in a campaign. The other lane only compares `dsi_generation()`.
- Fonts: `LanguageSetting.GetFont(style)` by name (0 = body, 2 = titles). It is cached per `dsi_generation()` and called
  only after the game has loaded `_fontSO`. Body material = the font asset's own material (as before: no outline).
  Fallbacks: the old sources (Txt_Notice font, Cinzel found by name). `txt_style(cinzel=1)` (exported, also used by
  Custom Modes) now gets the language's title font. The lobby title uses it too.
- Game words (`mpm_word` in the model, `game_word` on the game side: `TextKeyExtensions.GetText` by name, cached per
  language, only on the title / in a world; "TextKey not found" = our English). Labels that are game terms:

| English | TEXTKEY | where |
|---|---|---|
| Population | TEXTKEY_Shared_Population_NAME | Rules row label + tooltip title |
| Experience | TEXTKEY_Shared_EXP_NAME | Expedition Rules row label |
| Start | TEXTKEY_Common_Start | host page Start, lobby Start, its tooltip title |
| Back | TEXTKEY_Common_Back | title Back, its tooltip title |
| Cancel | TEXTKEY_CommonPopUp_Cancel | Cancel join, every box's Cancel |
| Load Campaign | TEXTKEY_SystemMenu_LoadCampaign | Esc tooltip title (the stock button's own label first) |

  Game words inside our own sentences (left in TR text; translators: use the game's term): Storage
  (TEXTKEY_BuildingType_Storage, "Own storage", "settlement storage"), Recruit (TEXTKEY_RecruitUI_Recruit,
  "Recruiting", "Recruits"), Dungeon (TEXTKEY_Shared_Dungeon_NAME, "Dungeon loot"), Portal
  (TEXTKEY_DungeonResultUI_Portal, "the Portal screen"), Level (TEXTKEY_Shared_Level_NAME, "levels"), Event
  (TEXTKEY_EventNodeUI_NAME, "Event choices"), Experience (TEXTKEY_Shared_EXP_NAME, "experience gained"), Population
  ("Population full", "population limit"), Load (TEXTKEY_SaveLoad_Load, "the load list"), Save (TEXTKEY_Common_Save).
  "Gear", "Clan", "New Campaign" have no row of their own in the table: our words.

# Lane i18n-game (in-game UI)

Branch `i18n-game` (from main bea54f9). Files: `src/ui_game.c`, `src/ui_teams.c`, `src/ui_model.c` (+ `.h`),
`src/ui_tip.c`, new `src/ui_utf8.h`, `src/ds_i18n.h` (shared core, copied unchanged), the ui tests.
The menu lane (`i18n-menu`) owns mpmenu*, mp_*, ord_*, net/** and the one `DSI_IMPLEMENTATION` of the dylib.

### How it was done (re-runnable)
- `tools/i18n_wrap.py` + `tools/i18n_rules/<file>.py`. Every change in the four .c files comes from the rules:
  `git checkout main -- src/ui_game.c src/ui_teams.c src/ui_model.c src/ui_tip.c && python3 tools/i18n_wrap.py`
  gives the same files (a second run says "no change"; `--check` exits 1 when something would change).
  On a newer main: run it, read the `MISS` lines (an anchor moved: fix that rule), build, read the diff.
- Generic part: the string literals in the arguments of the text sinks get `TR()` (`notice`, `snprintf` format and
  its literal arguments, `tip_at`, `tip_on`, `tmp_set`, `line_text`, `plist_set`, `set_text`, `center_msg`).
  A format with no other argument becomes `"%s", TR("...")`. `TR("<color=#rrggbb>Word</color>")` becomes
  `ui_col("#rrggbb", TR("Word"))`, so the colour stays out of the translated text (45 in ui_game, more in ui_teams).
  `·` and friends inside TR texts are written as the UTF-8 character (see CORE CHANGE).
- Hand rules (EDITS): whole sentences instead of glued pieces, plurals, tables, by-value fixes, helpers.
- `.gitignore`: `!/tools/` added (tools/ was ignored by `/*`).

### What is wrapped
About 490 keys from these files (`tools/i18n_tool.py extract` on them: 492). ui_game 235 TR sites, ui_teams 129,
ui_model 73. Status lines, HUD tags, notices, tooltips (titles + bodies, the 18-row cog table), player list and
cog rows, spectator / viewer banner, lend menu, minimap, pings, population line, Teams screen and Going panel.
- Glued pieces made into one format each: "%s belongs to %s (Admin mode lets the host take it)" / "%s belongs to
  %s"; "Watching %s's world" / "Watching %s's expedition"; "Population full (%d/%d): host rule %s" / "Population
  full for you (...)"; "Waiting for %s (loading)", "Waiting for %s (%d of %d agree)", "%s said no: staying here" /
  "... staying on floor %d" / "The vote said no: ..."; " · %d s, then you decide" / " · %d s, then %s decides";
  "%s, away" (owner tags); ui_teams: "Region", "Waiting for: %s", "No answer from %s: expedition cancelled" ...
- Plurals (TRN): "%s wants %s · press >> to agree" / "%s want ..."; "sees this too" / "see this too"; "looks at the
  same part of the map as you." / "look at ..."; ui_teams "%d unit · max %d" / "%d units · max %d".
- Tables keep English with TR_NOOP and translate where drawn: cog tooltip rows, on/off rows, colour names
  (ui_model `color_names[]`, `ui_palette_name` returns TR), region names (fallback).

### Not wrapped, on purpose
- rig_log lines, rig/test commands and their JSON, file paths, class / sprite / TEXTKEY names, strcmp'd test words.
- `ui_default_player_name()` "Player": it is the default player NAME sent to the others (content, not UI).
- The red "X" disconnected marks, the dot and arrow glyphs, "✓" (a glyph; its fallback "yes" is TR).
- ui_teams: `region_line` (log/test text), the 22x22 "RUN" fallback tag, `side_s`, `ui_teams_model.c tm_header_text`
  (only the tests use it).
- Translator notes: keys with spaces at the edges are on purpose (", ", " and ", " (you)", " · %d s, then ..."):
  keep or drop the spaces as the language needs. Fragments shown alone: "resyncing", "loading", "catching up",
  "in sync", "Per player", "Split equally", "Multiplied", "Shared" (host Population rule names; the menu lane has
  the same words in its rule tables), "go down", "enter the dungeon" ... (verb phrases after "%s wants to %s.").
